# Car Prediction

Regression project that predicts the selling price of a used car from its
characteristics, with a Streamlit web interface for manual price estimation.

## Project structure

```
car-prediction/
├── app/
│   └── app.py                  Streamlit UI ("Driver Station")
├── data/
│   ├── raw/
│   │   └── car-price.csv       Source dataset (4,340 rows)
│   └── processed/
│       └── cleaned_cars.csv    Generated by src/cleaning.py
├── model/
│   └── random-forest-model.pkl Serialized model used for inference
├── notebooks/
│   ├── linear_regression.ipynb
│   ├── random_forest.ipynb     Tuned model, saves the .pkl artifact
│   ├── svr.ipynb
│   └── xgboost.ipynb
├── src/
│   ├── explore.py              Loads the raw dataset
│   ├── cleaning.py             Imputation, dedupe, encoding
│   ├── training.py             Compares the four models
│   └── predict.py              One-off prediction from the saved model
├── requirements.txt
└── README.md
```

## Setup

```bash
pip install -r requirements.txt
```

## Usage

All commands are run from the repository root, because every path in the
project is relative to it.

```bash
# Web interface
streamlit run app/app.py          # http://localhost:8501

# Train the four models (this also rewrites data/processed/cleaned_cars.csv)
python -m src.training

# Predict a single hardcoded car record
python src/predict.py

# Notebooks (paths inside are relative to notebooks/)
cd notebooks && jupyter lab
```

Use `python -m src.training`, not `python src/training.py`: the modules use
relative imports and therefore need to be run as a package module.

## Pipeline

1. `src/explore.py` reads `data/raw/car-price.csv`.
2. `src/cleaning.py` fills missing categorical values with the mode and
   missing numeric values with the median, drops duplicate rows (4,340 →
   3,672), one-hot encodes `fuel`, `seller_type` and `transmission`, maps
   `owner` to an ordinal scale, and writes `data/processed/cleaned_cars.csv`.
3. Training and the notebooks split the data 80/20 with `random_state=10` and
   tune each model with `GridSearchCV(cv=5, scoring="neg_mean_absolute_error")`.
4. `notebooks/random_forest.ipynb` persists the best estimator to
   `model/random-forest-model.pkl`, which is what the app and
   `src/predict.py` load.

Target: `selling_price`. Features: `year`, `km_driven`, ordinal `owner`, and
one-hot `fuel_*`, `seller_type_*`, `transmission_*` (13 columns). The `name`
column is dropped.

## Results

Recorded in the notebooks on the 20% test split (`random_state=10`):

| Model | MAE | RMSE | R² |
| --- | --- | --- | --- |
| Random Forest (grid) | 189,128 | 396,359 | **0.556** |
| XGBoost (grid) | 191,929 | 412,605 | 0.519 |
| Linear Regression | 215,520 | 439,056 | 0.455 |
| SVR (grid) | 253,497 | 579,523 | 0.051 |

Random Forest is the best model and is the one served by the app.
